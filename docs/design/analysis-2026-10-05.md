# paged.web — full analysis

**v1.0 · 2026-10-05 · input for the performance, testing and browser-parity work**

What `paged.web` is today, measured against two references: **Chrome** for layout, line
breaks and pixels, and **InDesign** for what a baked web frame becomes after IDML export.
What ships is listed in [`status.md`](../status.md); this record is the analysis behind the
next round of work and the corrections it made to other records.

Evidence tags, used on every claim that matters:

- **[C]**: verified by reading code or by grep on 2026-10-05.
- **[M]**: measured on 2026-10-05 by running it.
- **[S]**: reported by a survey and not re-verified. Treat it as a lead.

Paths are relative to this repository; `B` stands for `packages/web-bundle/src`, `R` for
`packages/web-render/src`. Line numbers are read at commit `653a95e` (before the fixes in
§10).

---

## 1. Method

Three read-only surveys (performance hot paths; tests and CI; features against Chrome and
InDesign, the feature registry, the platform gap register and the host doors), then a
re-check of every headline claim by grep against this repository, the engine
(`paged-media/core`) and the plugin contract (`paged-media/plugin-sdk`). Every gap is
classified by where it would have to be closed:

| Class | Meaning |
|---|---|
| plugin-only | closable in this repository with the doors that exist |
| no plugin door | the host has the capability but offers the plugin no door to it |
| not on the wire | core models it, the protocol does not carry it |
| not modelled in core | the engine has no model for it (or carries a field it ignores) |
| host UI | the editor shell would have to offer it |

## 2. Headline

1. **Undo of "Save to document" did nothing visible.** The save wrote the metadata label
   (undoable) and a container part (`<frame>/source.json`; plugin-api's `PartsSurface` is
   not undoable). Every reader preferred the part (`B/panels/web-source-panel.tsx:448`,
   `:494`, and the readers in `B/bake.ts`, `B/bake-to-document.ts`,
   `B/render-flow-command.ts`), so undo restored a label nobody read, and label and part
   diverged. [C; red specs against the real engine, §10]
2. **Sources over 64 KiB broke.** The engine refuses a metadata value over 64 KiB
   (core `paged-mutate` `apply/layer.rs`, `PLUGIN_METADATA_MAX_BYTES`). Insert and import
   sent the whole source as the label inside the insert batch, so a large `.html` failed the
   whole batch with only a log line (`B/insert.ts:86`); a large save wrote the part but not
   the label, and the panel showed "Unsaved edits" forever. [C; red specs, §10]
3. **Unsaved panel edits vanished** on a selection change and on an undo that changed the
   source: the editor remounts (`B/panels/web-source-panel.tsx:616`) and the draft lived only
   in the mounted editor. [C; red spec, §10]
4. **The TypeScript lane could not fail.** `.github/workflows/vitest.yml:90` ended in
   `|| true`, and the workflow did not run on pull requests. [C]
5. **The Rust suite ran nowhere.** 115 tests in `packages/web-render` (the lowering, the
   real-Blitz capture and the whole fragmentation ladder) were run by no workflow; the
   vitest job only built the crate to wasm. On the day `cargo fmt --check` and
   `cargo clippy -D warnings` (current stable) both failed. [C, M]
6. **Publishing did not follow green tests.** `publish.yml` ran on every push in parallel
   with CI, tested nothing, and skipped a version already on npm — a code change without a
   bump was a green run that shipped nothing. [C]
7. **Scene text is redrawn in the document's default face.** Layout shapes with the one
   bundled face (Inter Regular, `R/fonts.rs`); the C-1 text item carries `family`/`style`
   only as hints, and core renders every scene text run in the document default face (core
   `paged-compose` `scene_layer.rs` `SceneTextItem`, core `paged-renderer`
   `pipeline/text_frame.rs`). No bold, italic or web font reaches the canvas. [C]
8. **Bake is quadratic in text runs and takes many undo steps.** Per run: a story-id
   snapshot (`collection("stories")`), `insertTextFrame`, another `collection("stories")` to
   find the new story by diffing, then three more `mutate` calls
   (`B/bake-to-document.ts:79,89,300-316`). Rectangles and paths are one `mutate` each. [C]

## 3. Inventory [C]

- **Commands (7):** insert web frame, render web frame to canvas, render web flow, thread
  web flow, unthread web flow, thread into the second named flow, bake web frame to
  document (`B/activate.ts`, manifest `contributes.commands`).
- **Panel (1):** "Web frame" — HTML/CSS editors (host code-editor widget or a textarea
  fallback), sandboxed iframe preview (`sandbox=""`), diagnostics, four templates, template
  variables, tag outline, paste-and-sanitise, flow picker, last-render readout, explicit
  save.
- **Importer (1):** `.html` / `.htm` (`B/activate.ts`, `web-model/src/import-html.ts`).
- **Object type + edit context:** `webFrame`; double-click opens the panel
  (`B/edit-context.ts`).
- **Engine:** `packages/web-render` (Blitz 0.3.0-alpha.4: Stylo, Taffy, Parley), a 9.2 MiB
  wasm (2.43 MiB brotli) [M] with string-in, JSON-out exports `render_web_frame` and
  `render_web_flow`.

## 4. Fundamentals against Chrome and InDesign

| Fundamental | Reference | paged.web today | Class |
|---|---|---|---|
| Block, inline, flex, grid, table layout | Chrome | Blitz (Taffy) lays them out; never compared with Chrome | plugin-only (an oracle) |
| Line breaks | Chrome line boxes | Parley with one bundled face; never compared | plugin-only |
| Web fonts, bold, italic on the canvas | `@font-face`, weight, style | shaping uses Inter Regular only; core redraws scene text in the document default face | not modelled in core (face hints ignored) + plugin-only (faces into Parley) |
| Document fonts in layout | — | reach only the panel preview | plugin-only |
| Images, CSS backgrounds | `<img>`, `background-image` | no resource loading; image lowering built but never fed from HTML | plugin-only (a provider over parts and assets) |
| Gradients, shadows | Chrome paint | lowered to C-1 items | — |
| Fragmentation across frames | Chrome print fragmentation; InDesign threaded frames | relayout per frame; splits between blocks, lines, container children, table rows; no `break-*`, orphans, widows | plugin-only |
| Overflow policies | InDesign overset, auto-size | clip only; overset reported for flows | plugin-only + host UI |
| Re-render on change | live | only on command; not on save, resize or reopen | plugin-only (geometry change events exist) |
| Stale layers cleared | — | `sceneLayer.clear` never called | plugin-only |
| Preview equals canvas | — | the preview uses the viewport width and a body class for media; the canvas uses the frame width | plugin-only |
| In-frame text editing | InDesign type tool | none; double-click opens the panel | plugin-only + host UI (a modal session) |
| Undo of a save | one step | fixed (§10) | — |
| Large sources | — | fixed (§10) | — |
| Bake in one undo step | InDesign place | several steps per bake | not on the wire (no one-batch text-frame insert that answers story ids) |
| Bake fidelity after IDML export | InDesign opens it | solid fills, single-subpath paths, text frames; no strokes, gradients, images, multi-subpath paths, alpha | plugin-only for most; never checked in InDesign |
| Container parts and undo | — | parts are not undoable; worked around (§10) | not modelled in core |

The specs are mostly structural, against mocked hosts; a real-engine lane
(`REQUIRE_REAL_ENGINE=1`, the headless host with the published engine) covers insert,
metadata, fonts, flow and bake. No browser oracle, golden images, property tests or budgets.
The editor's pixel journey for web rendering skipped, rather than failed, when the engine
wasm did not load. The local engine artifact was two and a half months older than the Rust
sources, and nothing said so.

## 6. Performance, read from code, not yet measured

Every render starts from scratch:

- a new Parley font context per render (`R/capture.rs:803`, `R/flow.rs:159`, both calling
  `R/fonts.rs:53`) [C];
- the HTML parsed again for each flow group (`B/bake.ts:522`) [C];
- per frame of a flow, a full resolve and a repaint of the whole remainder
  (`R/flow.rs`, rung 2 and later) — O(frames × remaining content) [S];
- run-text recovery compares every painted run with every recovered run
  (`R/capture.rs`, `attach_run_texts`, nested loops) — O(R²) [C];
- bake: seven awaited host calls per text run, two of them full story-collection reads
  (§2.8) [C];
- the open panel reads the whole `fonts` collection on every document change
  (`B/panels/web-source-panel.tsx:466`) [C].

No bench, counter or budget exists. They are measured as counts before any is changed.

## 7. Records that disagree with the code

- `CLAUDE.md` said the document is written only by "Save to document"; insert, import,
  "Make web frame" and the thread commands also write it, and the container part was not
  mentioned. Corrected.
- `README.md` said rendering is gated on an engine spike and overflow waits for the engine
  lane, and listed no `web-render` package. Corrected.
- Code comments described the engine as future work (`B/bake.ts:18-35`, `R/lib.rs:56-103`,
  `R/flow.rs:18-37`, `B/activate.ts:18-24`, `web-model/src/render.ts`,
  `web-model/src/index.ts`); `web-model/src/css-flow.ts` said multiple named flows were not
  done; the disabled Overflow control said other policies "ship with the engine rendering
  lane". Corrected.
- The engine stamp written into every saved envelope named `anyrender` 0.11.0; the lockfile
  builds 0.10.0. Corrected; a spec compares the stamp with the lockfile.
- Feature registry rows cited 13 web-model tests (177 run), an old editor pin, a planned
  editor surface that has shipped, and Rust suites no workflow ran; three rows had no linked
  test. Corrected in the registry.
- Two gap-register rows were open although the work had landed (fragmentation below block
  granularity; font bytes for the preview). Closed there, with evidence.

## 8. The work, in one screen

Gates and pins first; a counting harness with budgets; the quadratic paths removed and
proven by those budgets; a Chrome oracle for layout and line breaks and an InDesign check of
baked frames; persistence and reachability (re-render on change, clear stale layers, preview
equal to canvas, live overflow policies); fidelity (faces, images, a richer bake); in-frame
editing; layout coverage; and one engine protocol change for the core gaps in §4 (scene text
in its own face, a one-batch text-frame insert that answers story ids, undoable parts or an
atomic label-and-part write).

## 10. Changed since the analysis (2026-10-05)

- **Undo follows saves.** One reader (`loadWebSource`) and one writer (`writeWebSource`) in
  `B/source-part.ts`. A source that fits stays inline in the label. A larger one goes to a
  content-addressed part, `sources/<hash>.json`, written once and never overwritten, and the
  label holds a pointer `{ ref: { hash, bytes } }`; undo restores the label, and the label
  names the live source. A spec fails if anything else in `B` reads metadata or parts.
  Saved versions of a large source accumulate as parts; nothing removes them yet.
- **Large sources** save, insert and import; no label over the cap is sent; a refusal is a
  diagnostic and, in the panel, a message beside the save button.
- **Drafts** are kept per frame in the panel and come back, still unsaved.
- **Gates.** vitest fails on a red spec and runs on pull requests; a `rust` workflow runs
  fmt, clippy (both feature sets) and both test runs; publish runs after green CI on the
  tested commit, tests the wasm it builds, and refuses a source change without a version
  bump (`scripts/package-hash.mjs`). `scripts/build-wasm.sh` refuses a wasm-bindgen CLI that
  differs from the lockfile and stamps the source hash, which `wasm-fresh.spec.ts` checks;
  `sdk-pin.spec.ts` and `engine-pin.spec.ts` pin the plugin contract and the engine stamp.
- **Counts after** [M]: web-model 183 passed, 9 skipped; web-bundle 165 passed (23 files);
  web-render 63 and 115, unchanged.
